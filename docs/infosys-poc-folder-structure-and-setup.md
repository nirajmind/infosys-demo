## 3. Key Architectural Benefits

### A. Zero Blast Radius via Selective Tagging (`--select-tag`)
Each domain is isolated using tags:
* `domain:infydigital`
* `api:ccp-services`

When decK executes:
```bash
deck gateway sync build/domains/infydigital-ccp-kong.yaml --select-tag "domain:infydigital"
```
It **only** creates, updates, or deletes entities carrying `domain:infydigital`. All other ~3,000 APIs in Konnect remain completely untouched.

### B. Elimination of the 23 MB Monolithic File
In the original test dump (`kong-onprem-gw-test-bkp.yaml`), Azure AD OIDC and ACL plugins were duplicated ~1,800 times on individual routes. Under this restructured architecture:
* Shared policies are declared once under `platform/`.
* Developers maintain lightweight, readable `openapi.yaml` files (~50–100 lines).

## 4. How to Execute the Setup

### Step 1: Recreate Folder Tree and Place Files
Run the following in PowerShell from your repository root:
```powershell
New-Item -ItemType Directory -Path ".github\workflows" -Force
New-Item -ItemType Directory -Path "demo-restructured\domains\infydigital\ccp-services" -Force
New-Item -ItemType Directory -Path "demo-restructured\platform\plugins" -Force
New-Item -ItemType Directory -Path "demo-restructured\platform\consumers" -Force
New-Item -ItemType Directory -Path "demo-restructured\build" -Force
New-Item -ItemType Directory -Path "scripts" -Force
```
*(Or on Linux/macOS: `mkdir -p .github/workflows demo-restructured/domains/infydigital/ccp-services demo-restructured/platform/plugins demo-restructured/platform/consumers demo-restructured/build scripts`)*

Move the attached files into the respective folders as shown in Section 1.

---

### Step 2: Local decK Build & Tagging (Manual Verification)
To compile the developer contract and apply infrastructure routing patches locally:
```bash
# 1. Convert OAS spec to Kong format and apply infrastructure patches
deck file openapi2kong -s demo-restructured/domains/infydigital/ccp-services/openapi.yaml | \
  deck file patch demo-restructured/domains/infydigital/ccp-services/patches.yaml | \
  deck file add-tags -o demo-restructured/build/infydigital-ccp-kong.yaml "domain:infydigital" "api:ccp-services"

# 2. Validate schema
deck file validate demo-restructured/build/infydigital-ccp-kong.yaml
```

---

### Step 3: Start the Local Data Plane (DP)
```powershell
.\scripts\start-dp.ps1
```
*(Or on Linux/macOS: `./scripts/start-dp.sh`)*

* **Control Plane Endpoint:** `0646a7d680.us.cp.konghq.com:443`
* **Local Proxy Endpoints:**
  * HTTP Proxy: `http://localhost:8010`
  * HTTPS Proxy: `https://localhost:8453`
  * Status API: `http://localhost:8101/status`

The script polls the Status API until configuration hash synchronization from Konnect CP is confirmed.

---

### Step 5: Trigger the GitHub Actions CI/CD Pipeline
Once committed to GitHub, the `.github/workflows/kong-konnect-apiops.yml` pipeline automates the 5 stages:
1. **Stage 1 (Validate):** Syntax check of all OpenAPI specs.
2. **Stage 2 (Lint):** Spectral governance enforcing corporate API design rules.
3. **Stage 3 (Build):** Assembles domain declarative files with `domain:infydigital` tags.
4. **Stage 4 (Diff):** Runs `deck gateway diff` with `--select-tag "domain:infydigital"`.
5. **Stage 5 (Sync):** Runs `deck gateway sync` with `--select-tag "domain:infydigital"` followed by zero-drift verification.
